# MVP 기획서 — 바이브 성적표 (Day 2, 2026-08-13 / **v3 확정** — grill Q1~Q11 통과, 기록: docs/grill-log.md)

> `npx scored` 한 줄이면 AI 코딩 세션 데이터(`~/.claude/projects/*.jsonl`)를
> **내 머신에서** 분석해 대시보드 + 재미 성적표를 생성. 무업로드 · 비로그인 · 무백엔드.

## 한 줄 가치

"내가 Claude Code를 어떻게 쓰는지"를 대시보드(실용) + 성적표(재미)로 보여주고, 자랑하고 싶게 만든다.
(실용 = 토큰·활동 대시보드, 재미 = 유형·문구·공개 연출 — 재미를 빼도 대시보드로 선다)

## 데이터 흐름 (v3 확정 — npx 진입 + 웹 승인)

1. 랜딩에서 `npx scored` 복사 → 터미널 실행
2. CLI(Node, 무의존성 지향)가 `~/.claude/projects/*.jsonl` **자동 탐색·파싱** — 사용자가 숨김 폴더 찾을 필요 없음
3. 집계 결과 JSON(수 KB)을 압축 인코딩해 `scored.kr/report#<data>`로 브라우저 자동 오픈 (도메인 `scored.kr` — 2026-08-15 구매 완료, 레포명 `scored`와 통일)
4. 웹은 URL 해시에서 데이터를 읽어 렌더링 — **해시는 서버로 전송되지 않는다** = 무업로드 유지
5. 공유: 카드 이미지 저장 + 결과 링크(해시 포함 URL 그대로 = 공유 링크 공짜). 동적 OG만 쿼리 파라미터 필요 → **공유 버튼 클릭 시에만** 카드 요약 스탯을 쿼리로 변환 (SCR-6에 고지)

원문 대화 내용은 URL에 싣지 않는다(용량 + 공유 시 프롬프트 원문 유출 사고 방지).
대시보드는 **집계 데이터만**, 원문은 CLI가 선별한 **짧은 발췌 하이라이트**(명대사·삽질의 순간 1~3개)까지만 허용.

**발췌 웹 승인 방식 (grill Q7 확정)**: 결과 페이지 진입 즉시 주소창 URL에서 발췌 데이터 제거(`history.replaceState`, 데이터는 메모리 유지) → 성적표 화면에서 실물 카드로 확인 → 공유 단계(SCR-5)에서 발췌 포함/제외 토글 후에야 발췌 포함 공유 URL 생성. 주소창 URL 실수 복사로 인한 원문 유출 원천 차단.

**신뢰 장치 (grill Q9·Q11 확정)**: 레포 전체 public(kjjyyy01/scored, 시크릿 스캔 완료) — CLI는 같은 레포 `cli/` 폴더, npm `repository` 필드 연결, 랜딩·런칭 포스트에 GitHub 링크 게시. provenance 배지는 v1.1.

|---|---|---|---|
| SCR-1 | 랜딩 | 가치 제안 1줄, `npx scored` 복사 CTA, **샘플 성적표 미리보기** + **"명령어 나에게 보내기"**(모바일 공유시트/클립보드로 명령어 전송 — grill Q2), GitHub 링크, "서버 전송 0" 배지 | 기본 / 복사됨 |
| SCR-2 | 결과 진입 + 공개 연출 | 해시 디코딩 → 성적표 공개 연출 (**재미 장치 1개 — 두구두구·등급 릴**) | 연출 / 해시 손상·구버전 |
| SCR-3 | 성적표 | 개발자 유형 + 등급 + 재미 지표 카드 + 유머 코멘트 + 발췌 하이라이트 | 정상 / 데이터 부족(세션 3개 미만) |
| SCR-4 | 대시보드 | 토큰 사용량 추이, 활동 히트맵(요일×시간), 도구 분포, 세션·프롬프트 스탯 — 성적표와 탭/스크롤로 오가는 실용 축 | 정상 / 데이터 부족 |
| SCR-5 | 공유 카드 | 요약 카드 이미지 생성 → 저장·클립보드, 결과 링크 복사, 동적 OG 미리보기 | 카드 생성 / 저장 완료 |
| SCR-6 | 처리 방식 안내 | "분석은 전부 내 컴퓨터에서, 서버 전송 0" 상세 + 공유 시 쿼리 전송 범위 고지 + 분석 도구(GA4) 고지 | 단일 |

- 공유 트리거(SCR-5)는 PLAN Day 1 산출물 ③에 따라 SCR 1개로 계상
- **Day 9 컷 우선순위 (뒤에서부터 컷, grill Q1·Q8 확정)**: 동적 OG → 발췌 하이라이트 → SCR-6 별도 화면(랜딩 섹션으로 격하) → **대시보드 화면 전체(SCR-4) — 성적표 내 숫자 카드 4개로 격하** → 공개 연출 축소(페이드 1종). SCR-1·2·3·5 코어와 이미지 저장은 사수

## 추출 지표 (JSONL 파싱 스펙 v1)

실데이터 검증 완료 (2026-08-13, 로컬 263개 세션 파일 샘플링). 파싱 주체는 **CLI(Node)** 로 이동 — 지표 정의는 동일.

**레코드 필터**: `type: user|assistant`만 사용. `isMeta: true`, content가 `<`로 시작(시스템/명령), `isSidechain: true`(서브에이전트)는 프롬프트 카운트에서 제외.

### 성적표 지표 (재미)

| 지표 | 소스 필드 | 성적표 표현 |
|---|---|---|
| 새벽 코딩 지수 | `timestamp` 00~06시 비율 | "새벽형 인간 상위 N%" |
| 사과 카운트 | assistant text "죄송/미안" 빈도 | "AI가 N번 사과했습니다" |
| 최장 삽질 | 연속 `tool_result.is_error` 구간 | "최장 N연속 에러의 늪" |
| 재시도 지수 | user text "다시/아니/왜" 빈도 | "인내심 등급" |
| 프롬프트 스타일 | 평균 길이, 한 줄 지시 vs 장문 | 유형 판정 입력 |
| 발췌 하이라이트 | 삽질 구간·특징 프롬프트 1~3개 (CLI 선별, 짧게) | "이달의 명대사" |

### 대시보드 지표 (실용)

| 지표 | 소스 필드 | 표현 |
|---|---|---|
| 토큰 사용량 | `message.usage` 합산 (일별) | 추이 차트 |
| 활동 히트맵 | `timestamp` 요일×시간 버킷 | 히트맵 |
| 도구 분포 | `tool_use.name` 카운트 | 상위 도구 차트 |
| 기본 스탯 | 세션 수·프롬프트 수·활동일·모델 분포 | 숫자 카드 |

**개발자 유형**: 지표 조합으로 **6유형** 판정 (grill Q6 — 유형당 문구 밀도 우선, 8종에서 축소) — 유형명·판정 규칙·문구는 콘텐츠 제작일(Day 7)에 확정. 잘린 2종은 backlog(v2 후보).

**파서 리스크 대응**: 미지 필드 무시(관대한 파싱), 알 수 없는 `type` 스킵, 지표별 독립 실패(부분 생성 허용). 결과 JSON에 스키마 버전 필드 포함(웹-CLI 버전 어긋남 대응).
