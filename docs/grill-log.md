## Day 1 (2026-08-12) — 아이디어 검증 grill

후보 4개가 순차로 grill을 거쳤다: 도전장(탈락) → 살까말까(중단) → 물줬어?(확정 후 당일 번복) → 바이브 성적표(최종 확정).

### 후보 ① 도전장 — Round 1 (5문항)

❓ **Q1 - 당신은 정말 이걸 주 3회 쓰는가**: 스코어링 1번 기준이었죠. 지금 이 자리에서, 이번 주에 실제 친구에게 보낼 도전장 3개를 구체적으로 말할 수 있나요? (누구에게, 무슨 미션) 못 만들면 "내가 쓸 서비스"가 아니라 "있으면 좋을 것 같은 서비스"고, 그건 Day 13 게릴라 테스트에서 무너집니다.
➡️ 직접 3개를 써보세요. 10초 안에 안 나오면 이 가설은 보류감입니다.
🧑 "주3회는 안쓸거같아."
📌 실제 보낼 도전장 3개가 떠오르지 않았음 — 본인 사용을 정직하게 부정. 스트라이크 1의 직접 원인.

❓ **Q2 - 비로그인인데 전적은 누구 것인가**: 차별점이 "가입 없이 링크로"인데, 재미 장치는 "전적이 쌓인다"예요. 가입이 없으면 전적을 쌓을 신원이 없습니다. (A. 전적은 도전장 페이지 단위 / B. 이름 입력 + localStorage / C. 계정 필요)
➡️ A 추천. "그 판의 결과"만으로도 경쟁·랭킹은 성립하고, 신원 문제가 통째로 사라집니다.
🧑 "A"
📌 권장안 수용 — 신원 문제를 구조적으로 제거하면서 차별점(비로그인)을 지키는 유일한 선택지. B는 기기 교체 시 증발, C는 차별점 자살.

❓ **Q3 - 인증 조작은 누가 막는가**: 사진 인증은 아무 사진이나 올리면 끝입니다. (A. 출제자가 판정 / B. 참여자 전원 투표 / C. 판정 없음)
➡️ A 추천. 구현이 버튼 2개고, "야 이게 인증이냐"라는 실랑이가 공유·재방문 트리거가 됩니다.
🧑 "A"
📌 권장안 수용 — 구현 최소(버튼 2개)이면서 친구 간 실랑이 자체가 재미·재방문 장치가 되는 일석이조.

❓ **Q4 - 일회성 미션인데 재방문율 15%가 왜 나오는가**: 일회성 = 반복 사유 없음 = 재방문 없음의 다른 이름. (A. 재방문=역도전, 킬 지표를 역도전율로 / B. 진행 중 도전장 확인이 재방문 유발 / C. 둘 다 계측, 판정은 재방문율)

❓ **Q9 - 원석 캐기**: 최근 2주, 돈·소비에서 구체적으로 뭐가 짜증났나요? 상황째로 말해주세요.

## Day 2 (2026-08-13) — MVP 기획서(docs/MVP.md v2) 스코프 방어 grill

### Round 1 (6문항)

❓ **Q1 - 대시보드는 v1 생존 자격이 있는가**: 대시보드를 통째로 빼고 성적표에 숫자 카드 4개만 남기면, 이 서비스는 무너지는가? 안 무너진다면 대시보드는 왜 v1인가? (a. v1 유지 / b. 숫자 카드로 축소, 대시보드 화면은 v1.1 / c. 유지하되 Day 9 컷 순위에 "화면 전체" 명시)
➡️ 권장: (c). 탈출구 없는 스코프는 Day 9에 사람을 잡습니다.
🧑 "c"
📌 권장안 수용 — 실용 축(재방문 근거)으로서 유지 가치는 인정하되, 일정이 밀리면 화면 전체를 버릴 수 있는 탈출구를 컷 순위에 명시해 스코프 리스크를 방어.

❓ **Q2 - 모바일 착지의 전환 장치**: 폰에서는 npx를 못 돌립니다. 모바일 방문자가 70%면 킬 지표 산술상 시작부터 13%p를 잃고 들어갑니다. (a. 샘플 성적표만 / b. "명령어 나에게 보내기" 추가 / c. 킬 지표 모수를 데스크톱 방문자로 재정의)
➡️ 권장: (b)+(c) 동시. 지표 정의는 지금 아니면 못 고칩니다.
🧑 "b, c"
📌 권장안 수용 — (b)는 네이티브 공유시트 API 수준이라 SCR 증가 없이 모바일→데스크톱 다리를 놓고, (c)는 판정일에 지표 해석으로 자신과 협상하는 사태를 예방.

❓ **Q3 - 발췌 하이라이트 — 재미의 핵심인가 사고의 씨앗인가**: "이달의 명대사" 원문 조각이 공유 URL에 실려 돌아다닙니다. 회사 코드명, 욕설, API 키 조각이 명대사로 뽑히는 순간 사고입니다. (a. v1 컷 / b. CLI에서 눈으로 확인 후 승인 / c. 자동 상한만)

🧑 "방법이 더 없나? CLI에서 확인하는 것 보다 실제 보게될 화면에서 보는 것이 나아보여서. CLI에서 카드가 실제로 볼 카드와 똑같으면 b로 진행"

❓ **Q4 - 동적 OG는 유입 엔진인가 장식인가**: 카드 이미지 저장·전송이 이미 있는데, 카톡·슬랙에서 이미지 첨부와 링크 미리보기 중 뭐가 실제 경로입니까? (a. 필수 / b. v1 컷, 정적 OG 1장 / c. 유지하되 Day 9 컷 1순위)

📌 용도 재확인 발언 — 동적 OG의 존재 이유(링크 미리보기에 내 성적표 카드가 뜨는 것)를 본인 언어로 확정. 컷 지위 문제만 Round 2 Q8로 분리.

### Round 2 (4문항)

❓ **Q7 - 발췌 확인을 웹 화면에서 (Q3 재설계)**: (d) 웹 승인 방식 — CLI는 발췌 포함해 열고 → 결과 페이지 진입 즉시 주소창 URL에서 발췌 데이터 제거(`history.replaceState`, 데이터는 메모리 유지) → 성적표 화면에서 실물 카드로 확인 → 공유 단계(SCR-5)에서 포함/제외 토글 후에야 발췌 포함 공유 URL 생성.

🧑 "CLI에서는 실제 보게 될 화면과 다른거지?"
📌 **(d) 확정** — CLI는 터미널이라 발췌를 텍스트 줄로만 표시 가능(실물 카드 표시 불가). 사용자의 전제 조건("CLI가 실물 카드와 똑같이 보이면 b")이 기술적으로 성립 불가하므로 (d)가 유일하게 요구를 충족. 부수 효과: 주소창 URL 실수 복사로 인한 원문 유출 원천 차단.

❓ **Q9 - 레포 공개 방법 (Q5 마무리)**: 레포 = GitHub 레포지토리. npm publish하면 CLI 코드는 어차피 누구나 볼 수 있게 됩니다.

📌 **전체 public 확정 (b)** — 전체 공개 시 (a)/(b) 구분이 사라지므로 베스트 구성으로 정리: CLI를 같은 레포 `cli/` 폴더에 + npm `repository` 필드 연결 + 랜딩·런칭 포스트에 GitHub 링크 (+ provenance 배지는 v1.1). 이유: "코드 직접 확인하세요" 한 줄이 GeekNews·디스콰이엇 댓글창 최고의 신뢰 방어막. 공개 시 PLAN.md·history.md·git 이력 전체가 함께 공개됨을 고지받고 인지 후 수용(과정 기록 = 구직 자산이라는 PLAN 철학과 일치).

❓ **Q10 - 킬 크라이테리아 문구 확정 (Q2=c 후속)**: "2주 후 **데스크톱 방문자** 중 결과 페이지 도달률 20% 미만, 또는 도달자 중 공유·저장률 10% 미만 시 피벗. 단 **데스크톱 방문 150명 미달** 시 판정 보류" (a. 이대로 확정 / b. 숫자 수정)
