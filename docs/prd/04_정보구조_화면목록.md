## 메타데이터·색인 규약

canonical·구조화 데이터의 단일 원본. 화면 문서 §13은 ID 없이 이 절을 참조만 한다. (2026-09-01 추가 — PLAN Day 17 기술 점검 항목인데 PRD에 명세가 없어 구현 근거가 비어 있었다)

| 라우트 | canonical | 색인 | JSON-LD |
|---|---|---|---|
| `/` | `https://scored.kr` | O (sitemap) | `SoftwareApplication` 1개 |
| `/how` | `https://scored.kr/how` | O (sitemap) | 없음 |
| `/report` | `https://scored.kr/report` | 사이트맵 제외 | **금지** |
| 404 | 없음 | X | 없음 |

- **canonical은 쿼리·해시를 뺀 경로만.** `?from=cli`(06)·`?from=report`(EL-RPT-008)는 GA4 세그먼트용 파라미터일 뿐 별개 문서가 아니다. 쿼리별로 색인되면 크롤 예산이 갈리고 유입 판정도 흐려진다. 해시는 서버로 전송되지 않으므로 canonical에 실릴 수 없다 (BR-004와 같은 방향).
- **`/report`에 `noindex`는 넣지 않는다.** 색인 가치는 없지만 사이트맵 제외로 충분하고, SNS 크롤러가 `robots` 메타를 어떻게 다루는지 보장할 수 없다. 공유 미리보기(F-005)는 v1 유입의 주 경로라 잃을 위험이 얻는 것보다 크다.
- **JSON-LD에 사용자 데이터 금지.** `/report`의 값은 전부 해시에서 나온 개인 활동 데이터다. 구조화 데이터로 내보내면 14 §5(성적 데이터 전송 금지)를 우회하는 경로가 된다. 정적 화면의 고정 값만 허용한다.

### JSON-LD 페이로드 (SCR-001 전용)

`SoftwareApplication` 1개. 값은 전부 고정이며 사용자·세션 데이터가 들어갈 자리가 없다.

| 필드 | 값 | 근거 |
|---|---|---|
| `name` | `scored` | CPY-COM-002 |
| `description` | 랜딩 메타 `description`과 동일 문자열 | 값 중복 방지 (문구 변경 시 한 곳만) |
| `applicationCategory` | `DeveloperApplication` | 타겟 = AI 코딩 도구 사용자 |
| `operatingSystem` | `macOS, Windows, Linux` | CLI-001 실행 환경 |
| `offers` | `price: "0"` · `priceCurrency: KRW` | 무료·비로그인 |
| `url` | `https://scored.kr` | canonical과 동일 (Next `metadataBase` 정규화 결과에 맞춘 무슬래시 표기) |
