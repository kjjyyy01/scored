# 런칭 포스트 초안 (Day 18~19)

> **상태**: 초안 — 사용자 검토 대기 (2026-09-02 작성)
> **런칭일**: 2026-09-08(화) = Day 20
> **채널 확정**: 커뮤니티 2개(GeekNews·디스콰이엇) + 소셜 2개(X·Threads). 당사자 채널 슬롯 미사용 (사용자가 코딩 커뮤니티 미소속)

## 채널 선정 근거

PLAN Day 18~19는 `채널 1~2개 선정 (국내: 디스콰이엇 + GeekNews)`를 지정한다. 한국어 서비스이므로 국내 2채널이 기본값이고, Day 10 판정에도 `주 채널은 GeekNews·디스콰이엇·X`로 적혀 있다.

**GeekNews가 1순위인 이유는 킬 크라이테리아다.** 판정 기준(15 §킬 크라이테리아)이 *"데스크톱 방문 150명 미달 시 판정 보류"*이고, CLI 실행이 데스크톱에서만 가능하므로 **표본 자체가 데스크톱 트래픽**이다. 디스콰이엇은 확산·피드백에는 좋지만 모바일 비중이 높아 150명이 모바일로 채워지면 판정이 보류된다. 개발자가 데스크톱에서 읽는 GeekNews가 표본을 만든다.

X·Threads는 커뮤니티 포스트가 아니라 본인 계정 확산이므로 PLAN의 `1~2개` 상한과 별개로 계산한다.

## UTM 규약

`utm_campaign`을 런칭일로 고정해 **판정 구간(9/8~9/22)과 겹치게** 한다. GA4에서 이 캠페인만 필터하면 킬 크라이테리아 분모가 바로 나온다.

| 채널 | 링크 |
|---|---|
| GeekNews | `https://scored.kr/?utm_source=geeknews&utm_medium=post&utm_campaign=launch-20260908` |
| 디스콰이엇 | `https://scored.kr/?utm_source=disquiet&utm_medium=post&utm_campaign=launch-20260908` |
| X | `https://scored.kr/?utm_source=x&utm_medium=social&utm_campaign=launch-20260908` |
| Threads | `https://scored.kr/?utm_source=threads&utm_medium=social&utm_campaign=launch-20260908` |

> 쿼리는 canonical에서 제거되므로 색인이 갈리지 않는다(2026-09-01 결정). `?from=cli`·`?from=report`와도 충돌 없다.

## ① GeekNews — 1순위

**제목**

```
scored — 터미널 한 줄로 만드는 Claude Code 하루 성적표 (서버 전송 0)
```

**본문**

```
Claude Code가 남긴 오늘 세션 기록을 읽어서 성적표로 만들어주는 도구입니다.

  npx @jong-yeon/scored

설치도 로그인도 없습니다. 세션 기록은 컴퓨터 밖으로 나가지 않고,
분석은 전부 브라우저에서 돌아갑니다.

동작 방식:
- CLI가 로컬 세션 로그를 읽어 통계만 뽑습니다 (의존성 0)
- 그 결과를 압축해서 URL 해시(#)에 실어 브라우저를 엽니다
- 해시는 서버로 전송되지 않으므로, 성적표 서버에는 아무 기록도 안 남습니다
- 링크를 공유하면 상대방 브라우저가 그 해시를 풀어서 같은 화면을 그립니다

즉 백엔드도 DB도 없습니다. 프롬프트 원문은 애초에 다루지 않고,
집계된 숫자와 등급만 담습니다.

등급·유형은 하루 활동으로 정해집니다.
"B+ · 에러의 늪 탐험가", "A · 마라톤 러너" 같은 식입니다.

https://scored.kr/?utm_source=geeknews&utm_medium=post&utm_campaign=launch-20260908
```

**톤 근거**: GeekNews는 마케팅 문구에 반응하지 않고 **"어떻게 만들었나"에 반응한다.** "재미있어요" 대신 **해시에 데이터를 실어 백엔드를 없앤 구조**를 전면에 뒀다 — 이 프로젝트에서 기술적으로 가장 할 말이 되는 부분이다.

만들면서 정한 원칙이 하나 있습니다 — 기록을 서버로 안 보낸다.
세션 로그에는 내가 뭘 만들고 있는지가 다 들어있으니까요.

써보시고 어떤 유형 나왔는지 알려주시면 좋겠습니다.

## ⚠️ 게시 전 반드시 처리할 것

1. **성적표 값을 본인 실제 값으로 교체** — 초안의 `B+ · 에러의 늪 탐험가 / 연속 에러 6회`는 **랜딩의 샘플 데이터**다. 남의 샘플을 "저는 이랬습니다"로 쓰면 거짓말이 된다. 런칭 당일 본인 성적표를 뽑아 그 값으로 바꾼다.
2. **헤드 자산 GIF** — PLAN Day 18~19가 *"재미 장치가 작동하는 순간의 GIF/영상을 헤드 자산으로 (스크린샷보다 전환이 좋다)"*를 지정한다. 여기서 재미 장치는 **리빌 연출**이며, 화면 녹화는 사용자 몫이다.
3. **링크 UTM 누락 점검** — PLAN은 `전 링크 UTM 필수`다. 게시 직전 각 글의 링크에 `utm_campaign=launch-20260908`이 붙어 있는지 확인한다.
